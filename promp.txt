=== ВЕРСИЯ ===
Minecraft 26.2, Fabric Loader + Fabric API, язык Java.
Код лёгкий, без лишних библиотек.

=== ИДЕЯ МОДА (название: jinfo) ===
Игрок пишет о себе текст, а другие игроки видят его в игре. Своего сервера и IP
нет, всё хранится в бесплатном Cloudflare Worker + D1 (без карты).
Мод должен работать и у игроков с лицензионным аккаунтом, и у тех, кто играет
без лицензии (offline-mode). Никаких проверок лицензии, которые отключают мод.

=== ЧТО УЖЕ СДЕЛАНО В CLOUDFLARE ===
- Worker с именем mcprofiles, адрес: https://mcprofiles.mcchopik.workers.dev
- База D1 profiles, привязана к Worker как env.DB
- Таблица: profiles(uuid TEXT PRIMARY KEY, data TEXT NOT NULL, updated INTEGER NOT NULL)
- Секреты Worker: TOKEN_KEY (для HMAC-токенов) и AES_KEY (строка 40+ символов;
  из неё получай 32-байтный ключ через SHA-256 для AES-GCM)
Если нужны новые таблицы (reports, offline_keys), дай SQL, я выполню его в D1 Console.
Страницы игроков на workers.dev пока НЕ делай, это возможно позже.

=== КОМАНДА /jinfo ===
- /jinfo help: подробная справка в чате (все плейсхолдеры, цвета, примеры)
- /jinfo edit: открыть экран редактора в игре
- /jinfo web: открыть редактор в браузере (локальный сайт, см. ниже)
- /jinfo set <текст>: быстро задать текст
- /jinfo me: показать мой профиль; /jinfo view <ник>: показать профиль игрока
- /jinfo clear: удалить мой профиль (и на сервере тоже)

=== ФОРМАТ ТЕКСТА И ПЛЕЙСХОЛДЕРЫ ===
Игрок пишет, например: «Привет, я Вася, мой канал {youtube} https://youtube.com/@vasya
а стримлю на {twitch} vasya».
Когда смотрят чужой профиль, {youtube} заменяется на красивую подпись с цветом
сервиса: «Ютуб: <ссылка>» (красный), «Twitch: ...» (фиолетовый) и т.д.
Подпись зависит от языка клиента (ru/uk/en), цвета у каждого сервиса свои.
- После плейсхолдера можно писать полную ссылку ИЛИ короткий ник/хэндл, мод сам
  собирает ссылку (https://youtube.com/@ник и т.п.).
- Сервисы: youtube, twitch, discord, telegram, tiktok, instagram, x (twitter),
  github, steam, vk, reddit, kick, boosty, donationalerts, modrinth. Список
  держи в одном месте в коде (enum/таблица: ключ, подпись по языкам, цвет,
  шаблон ссылки, разрешённые домены), чтобы легко добавлять новые.
- Универсальный {link:Название} https://...: для любого другого сайта со своей подписью.
- Цвета и стили как в Minecraft: &0-&9, &a-&f, &l жирный, &o курсив, &n подчёркнутый,
  &m зачёркнутый, &r сброс, плюс hex в формате &#RRGGBB. Символ § тоже понимай.
  &k (обфускация) не разрешай.
- Игрок не может вставить кликабельное событие или hover «в чистом виде»: ссылки
  делаются только через плейсхолдеры, которые мод проверяет.

=== РЕДАКТОР В ИГРЕ (экран по /jinfo edit) ===
- Многострочное текстовое поле, счётчик символов, живой предпросмотр справа/снизу.
- Панель кнопок: 16 цветов, hex-ввод цвета, жирный/курсив/подчёркнутый, сброс.
- Кнопки вставки сервисов (YouTube, Twitch, Discord и т.д.), по нажатию в текст
  добавляется плейсхолдер.
- Кнопки: «Сохранить» (локально + на сервер), «Отмена», «Очистить», «Открыть в браузере».
- Лимиты: 500 символов, 10 строк, максимум 6 ссылок. Предупреждение при превышении.

=== РЕДАКТОР В БРАУЗЕРЕ (локальный сайт, команда /jinfo web) ===
Мод поднимает маленький веб-сервер на моём устройстве и открывает редактор в браузере:
- Сервер: встроенный com.sun.net.httpserver.HttpServer из JDK (без библиотек), слушает
  ТОЛЬКО 127.0.0.1, порт случайный свободный (порт 0). Одновременно один экземпляр.
- Адрес содержит случайный секретный токен: http://127.0.0.1:<порт>/e/<токен>/ .
  Запросы без верного токена получают 404. Проверяй заголовки Host (только 127.0.0.1
  или localhost с нашим портом) и Origin для POST, чтобы закрыть DNS rebinding и
  подделку запросов с других сайтов. CORS не включай.
- Заголовки безопасности: Content-Security-Policy (default-src 'self', без внешних
  CDN, шрифтов и скриптов), X-Content-Type-Options: nosniff.
- Страница одна, лежит в ресурсах jar (HTML + CSS + немного JS, без фреймворков),
  работает без интернета: большое текстовое поле, кнопки цветов (16 + hex),
  жирный/курсив/подчёркнутый, кнопки вставки сервисов, счётчик символов и лимитов,
  две вкладки предпросмотра: «Подсказка» (как при наведении) и «Полный профиль»
  (как на полном экране, кнопки сервисов с цветами, но не кликабельные).
- Предпросмотр делает тот же Java-парсер, что и в игре: JS отправляет текст на
  POST /preview (с задержкой ~200 мс после ввода), сервер возвращает уже готовый
  безопасный HTML. Всё, что приходит от парсера, обязательно экранируй.
  Цвета Minecraft передавай как CSS-цвета.
- Кнопка «Сохранить»: POST /save, мод сам отправляет профиль на Worker через
  существующий сетевой клиент и возвращает странице результат (успех/ошибка/
  слишком часто). Токены и ключи никогда не отдаются странице.
- Открытие браузера: используй стандартный способ Minecraft/JDK для открытия ссылки;
  если не получилось, покажи ссылку в чате (кликабельную и копируемую).
- При открытии страница подгружает мой текущий профиль.
- Остановка сервера: через 30 минут без запросов, при закрытии мира/выходе из игры,
  по команде /jinfo web stop. Страница при этом показывает «сессия закрыта».
- Ситуации: порт занят (повторить с другим), браузер не открылся, страница открыта
  в двух вкладках (последнее сохранение побеждает, показывай предупреждение),
  несохранённые изменения при закрытии вкладки (предупреждение), ошибка сети при
  сохранении (текст остаётся в поле, ничего не теряется), игра закрыта (страница
  понятно сообщает, что мод не отвечает).

=== КАК ВЫГЛЯДИТ В ИГРЕ ===
1) Shift + ПКМ по игроку: открывается компактная карточка. В центре голова игрока
   (лицо из его скина, включая второй слой), снизу ник. Если у игрока есть профиль,
   рядом значок. У неподтверждённых профилей (см. ниже) значок «не подтверждён».
2) Навёл мышь на голову: показывается подсказка с оформленным текстом профиля
   (цвета, подписи сервисов вместо плейсхолдеров). Ссылки в подсказке НЕ кликабельны.
3) Кликнул по голове один раз: открывается полный экран мода: аватар, ник,
   полный текст, а каждый сервис оформлен кнопкой с цветом сервиса. Клик по
   кнопке: окно подтверждения «Открыть ссылку? Домен: ...» с полной ссылкой
   и кнопками «Открыть» / «Отмена». Автоматически ссылки никогда не открываются.
4) Клавиша из настроек Controls (по умолчанию P): открыть мой профиль.
5) Shift+ПКМ по игроку не должен ломать обычное взаимодействие, если меню не
   открылось. В конфиге есть галка выключить жест.

=== ДВА ТИПА АККАУНТОВ (как узнать, кто есть кто) ===
Определяй тип по версии UUID игрока:
- UUID версии 4: аккаунт Mojang/Microsoft. Подтверждение через joinServer + hasJoined (ниже).
- UUID версии 3: offline-аккаунт (UUID = nameUUIDFromBytes("OfflinePlayer:" + ник)).
  Подтвердить такой UUID через Mojang нельзя, поэтому используй ключи на клиенте:
  * При первом запуске мод создаёт пару ключей Ed25519 и хранит её локально
    (приватный ключ никуда не отправляется).
  * Worker при первой регистрации UUID запоминает публичный ключ (таблица
    offline_keys: uuid, pubkey, created). Дальше этим профилем может управлять
    только тот, у кого есть соответствующий приватный ключ. Кто первым занял
    ник, тот им и владеет.
  * Такие профили везде помечаются как «не подтверждён», и их нельзя выдать за
    профиль с UUID версии 4. Эти два пространства UUID не пересекаются.
- Мод всегда работает, даже если сессии Mojang нет: просто используется второй способ.

=== СИТУАЦИИ, КОТОРЫЕ НУЖНО ОБРАБОТАТЬ ===
- У игрока нет профиля: в карточке «Профиль не заполнен».
- Идёт загрузка: «Загрузка...» (запрос в фоновом потоке, игра не лагает).
- Нет сети, таймаут 5 с, ошибка Worker: понятное сообщение, повтор не чаще чем раз в 30 с,
  показать старые данные из кэша, если они есть.
- 429 (слишком часто): сообщение «подожди немного».
- Игрок вышел с сервера, пока открыто меню: меню продолжает работать по UUID.
- Ник сменился: всё привязано к UUID, а не к нику.
- Игрок смотрит на самого себя: используй /jinfo me или клавишу.
- Потерян файл с ключом offline-аккаунта: сообщить, что доступ к старому профилю
  утрачен, и дать способ сбросить его (например через 30 дней без активности).
- Опасные ссылки: разрешены только https; запрещены javascript:, file:, localhost,
  IP-адреса, ссылки с логином (user@host). Для встроенных сервисов домен обязан
  совпадать со списком, иначе плейсхолдер показывается как обычный текст без кнопки.
  Для {link:} любой https-домен, но с предупреждением в окне подтверждения.
  Подозрительные (сокращатели ссылок, punycode xn--) помечай предупреждением.
- Защита от подмены текста: вырезать управляющие и невидимые символы (zero-width,
  bidi-override вроде U+202E), ограничить повторяющиеся символы.
- Жалоба: кнопка «Пожаловаться» на экране профиля, отправляет на Worker (таблица
  reports: uuid профиля, uuid жалобщика, время). Один человек не чаще 1 жалобы на профиль в сутки.
- Много игроков: запросы батчем до 50 UUID, кэш в памяти (LRU 200 записей, TTL 10 мин),
  не спамить сервер запросами.

=== БЭКЕНД (Worker) ===
Один файл JavaScript, module syntax, привязки env.DB, env.TOKEN_KEY, env.AES_KEY.
- POST /auth (лицензионные): тело {username, serverId}. serverId клиент генерирует
  случайный (минимум 32 hex-символа, с префиксом «jinfo-», чтобы нельзя было
  использовать настоящий вход на игровой сервер). Worker проверяет через
  https://sessionserver.mojang.com/session/minecraft/hasJoined?username=...&serverId=...
  UUID берёт ТОЛЬКО из ответа Mojang. Возвращает токен uuid.expiry.hmacSha256, жизнь 1 час.
- POST /auth/offline (без лицензии): тело {username, publicKey, timestamp, signature}.
  Worker сам считает UUID из ника, проверяет подпись Ed25519 (WebCrypto) и что
  timestamp свежий (±2 минуты), сверяет/регистрирует публичный ключ в offline_keys
  и выдаёт такой же токен.
- PUT /profile: Bearer-токен, запись только для UUID из токена. Проверка: длина,
  чистка символов, ссылки. Хранение: AES-GCM (случайный IV), iv+ciphertext в base64.
  Лимит записи: 1 раз в 60 с на UUID.
- GET /profile/<uuid> и POST /profiles/batch (список до 50 UUID, ответ: у кого есть
  профиль, без текста): тоже только с токеном (любого из двух типов). В ответе
  у профиля есть признак verified (true для UUID v4, false для v3).
- DELETE /profile: удалить свой профиль.
- POST /report: жалоба (см. выше).
- Ошибки в JSON с правильными HTTP-кодами. НЕ логировать UUID, тексты и IP.
- Клиентская часть joinServer: используй актуальный способ для моей версии, если
  не уверен, скажи.
